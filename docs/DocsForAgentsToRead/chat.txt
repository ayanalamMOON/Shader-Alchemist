The Shader Alchemist (WebGPU/Compute Shader Assistant): A specialized engineering team for low-level graphics development.

The Team Architecture:

Math Architect Agent: Translates high-level visual descriptions (e.g., "a 3D fluid simulation grid with spatial hashing") into strict mathematical formulas and parallel execution bounds.

WGSL Writer Agent: Generates pure WebGPU Shading Language (WGSL) or GLSL code, targeting specific desktop and mobile WebGPU performance constraints.

Performance Evaluator Agent: Acts as a custom tool loop. It passes the code into a sandbox execution environment (like a lightweight headless browser runner via a tool call) to profile execution time, check for pipeline execution barriers, and prevent unaligned memory bounds.

Why it fits ADK: It leverages ADK's Sequential Orchestration ("Math \(\rightarrow \) Code \(\rightarrow \) Evaluate") and uses a state-driven loop to continuously optimize execution barriers until performance constraints are fully met. &#91;1&#93;

## System Architecture Overview
The Shader Alchemist is structured as a pipeline with a state-driven verification loop. Instead of generating WGSL directly from raw prompts—which often leads to memory alignment errors or poor workgroup utilization—the system separates domain logic into three distinct roles.
```
                  ┌───────────────────────────────────┐
                  │            USER PROMPT            │
                  │ ("3D fluid grid + spatial hash")  │
                  └─────────────────┬─────────────────┘
                                    │
                                    ▼
                          ┌──────────────────┐
                          │  Math Architect  │
                          └─────────┬────────┘
                                    │ MathSpec
                                    ▼
                          ┌──────────────────┐
                          │   WGSL Writer    │◄────────┐
                          └─────────┬────────┘         │
                                    │ ShaderArtifact   │ Refinement Loop
                                    ▼                  │ (Max iterations = N)
                          ┌──────────────────┐         │
                          │   Performance    ├─────────┘
                          │    Evaluator     │ (If constraints fail)
                          └─────────┬────────┘

## Agent Specifications &amp; State Schemas
### 1. Math Architect Agent
- **Goal:** Formalize spatial/physics constraints, parallel thread indexing, workgroup dimensional bounds, and buffer layouts into a deterministic specification.
- **Input:** Raw visual/algorithmic user request.
- **Output:** `MathSpec` structured payload.

JSON
```
{
  "algorithm": "3D Spatial Hash Grid",
  "workgroup_size": [64, 1, 1],
  "buffer_layouts": [
    {
      "binding": 0,
      "name": "Particles",
      "stride_bytes": 32,
      "fields": [
        {"name": "position", "type": "vec3<f32>", "offset_bytes": 0},
        {"name": "pad0", "type": "f32", "offset_bytes": 12},
        {"name": "velocity", "type": "vec3<f32>", "offset_bytes": 16},
        {"name": "hash_cell", "type": "u32", "offset_bytes": 28}
      ]
    }
  ],
  "mathematical_formulations": [
    "cell_index = floor(position / cell_size)",
    "hash = (cell_index.x * 73856093 ^ cell_index.y * 19349663 ^ cell_index.z * 83492791) % num_buckets"
  ],
  "barrier_requirements": ["storageBarrier() required before neighbor bucket traversal phase"]
}
```
### 2. WGSL Writer Agent
- **Goal:** Map the `MathSpec` into strict WGSL code while adhering to WebGPU memory alignment, subgroup capability flags, and binding models.
- **Input:** `MathSpec` + Feedback history from `Performance Evaluator`.
- **Output:** `ShaderArtifact` containing full WGSL, pipeline layout configurations, and dispatch parameters.

*Key Execution Considerations:*
- **Explicit Packing:** Enforce WGSL rule where `vec3<f32>` has an alignment requirement of 16 bytes.
- **Workgroup Memory:** Leverage `var<workgroup>` for shared tile caching when spatial locality benefits execution.

### 3. Performance Evaluator Agent
- **Goal:** Profile execution, catch web API pipeline creation errors, verify memory boundaries, and enforce latency budgets.
- **Input:** `ShaderArtifact`.
- **Tools Used:** Headless browser runner tool (e.g., Puppeteer / Playwright with `--enable-unsafe-webgpu` or Dawn headless bind).
- **Output:** Profiling metrics or explicit failure reports.

from google.genai.agent import Agent, SequentialPipeline, LoopBlock

# Agent 1: Math Architect
math_agent = Agent(
    name="MathArchitect",
    instruction="""Analyze the user visual requirement. Compute memory layouts,
    thread indexing schemes, and WGSL byte-alignment requirements. Write output to math_spec."""
)

# Agent 2: WGSL Writer
wgsl_agent = Agent(
    name="WGSLWriter",
    instruction="""Translate the math_spec into idiomatic WGSL code.
    Ensure struct fields comply with WebGPU 16-byte alignment rules.
    If state contains last_error, resolve the memory barrier or layout issue."""
)

# Agent 3: Performance Evaluator
evaluator_agent = Agent(
    name="PerformanceEvaluator",
    tools=[evaluate_webgpu_shader],
    instruction="""Run the evaluate_webgpu_shader tool on the generated code.
    Check execution time against target_budget_ms and capture validation errors.
    If it passes, set evaluation_passed=True. Otherwise, update last_error."""
)

# Refinement Loop Condition
def should_continue_loop(state: ShaderAlchemistState) -> bool:
    if state.evaluation_passed:
        return False
    if state.current_iteration >= state.max_iterations:
        return False
    return True

# Assemble ADK Architecture
shader_pipeline = SequentialPipeline(
    steps=[
        math_agent,
        LoopBlock(
            steps=[wgsl_agent, evaluator_agent],
            condition=should_continue_loop
        )
    ]
)
```
## Core Technical Challenges &amp; Solutions

|Technical Challenge|Root Cause|Agent Remediation Strategy|
|---|---|---|
|**Unaligned Uniform/Storage Buffers**|WGSL requires struct fields like `vec3` to align to 16 bytes.|The **Math Architect** explicitly inserts explicit padding variables (e.g., `_pad: f32`) into the `MathSpec` before code generation.|
|**Race Conditions in Parallel Writes**|Multiple workgroups writing to identical spatial hash buckets concurrently.|The **Performance Evaluator** detects non-deterministic memory state and instructs the **WGSL Writer** to use `atomicAdd` or multi-pass dispatch strategies.|
|**Driver Instability / GPU TDR**|Long-running compute loops trigger GPU timeouts (Timeout Detection and Recovery).|The **Performance Evaluator** tracks execution duration. If runtime exceeds threshold, it forces the **Math Architect** to re-partition thread blocks across multiple submit dispatches.|
## Value Demonstration: Spatial Hashing Example
To illustrate the transformation process, here is an example of how the agents convert a high-level request into parallel execution constraints.
### Mathematical Formulation (f(x))
Given a particle at 3D position p=(x,y,z) and a grid cell size s:
c=⌊sp​⌋
hash(c)=((cx​⋅p1​)⊕(cy​⋅p2​)⊕(cz​⋅p3​))(modN)
Where p1​,p2​,p3​ are large prime constants (73856093,19349663,83492791) and N is the bucket array capacity.
### Generated WGSL Execution Kernel
Code snippet
```
struct Particle {
    position: vec3<f32>,
    _pad0: f32, // Explicit 16-byte alignment enforce by Math Architect
    velocity: vec3<f32>,
    grid_hash: u32,
};

struct HashParams {
    cell_size: f32,
    bucket_capacity: u32,
    _pad1: u32,
    _pad2: u32,
};

@group(0) @binding(0) var<storage, read_write> particles: array<Particle>;
@group(0) @binding(1) var<uniform> params: HashParams;

fn calculate_spatial_hash(pos: vec3<f32>) -> u32 {
    let cell = vec3<i32>(floor(pos / params.cell_size));
    let p1 = 73856093u;
    let p2 = 19349663u;
    let p3 = 83492791u;

    let h = (u32(cell.x) * p1) ^ (u32(cell.y) * p2) ^ (u32(cell.z) * p3);
    return h % params.bucket_capacity;
}

@compute @workgroup_size(64, 1, 1)
fn main(@builtin(global_invocation_id) global_id: vec3<u32>) {
    let index = global_id.x;
    if (index >= arrayLength(&particles)) {
        return;
    }

    var p = particles[index];
    p.grid_hash = calculate_spatial_hash(p.position);
    particles[index] = p;
}
```

## 2. Core Agent Specifications &amp; Internal Workflows
### Agent 1: Math Architect Agent
- **Responsibility:** Structural, mathematical, and memory topology planning.
- **Input:** Raw User Query + Hardware Capabilities Target (e.g., Desktop Discrete GPU, Mobile WebGPU, Subgroup support enabled).
- **Internal Workflow:**
  1. Parse domain equations (e.g., SPH fluid dynamics, spatial binning, matrix ops).
  2. Map variable data types to WGSL primitives and calculate exact byte offsets and padding.
  3. Determine thread distribution: map problem domain N to workgroup dimensions (X,Y,Z) ensuring total invocations cover domain bounds without wasting threads.
  4. Identify execution hazards requiring barriers (`storageBarrier()`, `workgroupBarrier()`).

### Agent 2: WGSL Writer Agent
- **Responsibility:** Synthesizing valid WGSL compute code from `MathSpec` and optimizing bottlenecks flagged by Agent 3.
- **Input:** `MathSpec` + `EvaluationFeedback` (if in refinement loop).
- **Internal Workflow:**
  1. Construct `@group(X) @binding(Y)` layout decorations matching host memory buffers.
  2. Generate compute kernel function `@compute @workgroup_size(X, Y, Z)`.
  3. Implement local workgroup memory (`var<workgroup>`) tiling strategies where spatial temporal locality can be exploited.
  4. Apply feedback fixes: resolve validation errors, unpack unaligned structures, alter workgroup sizing, or eliminate bank conflicts/branch divergence.

### Agent 3: Performance Evaluator Agent
- **Responsibility:** Static analysis, headless execution, execution profiling, and diagnostic reporting.
- **Input:** `ShaderArtifact` (WGSL code + pipeline configuration).
- **Internal Workflow:**
  1. Invoke the **Headless WebGPU Profiler Tool** using an isolated browser context (e.g., Chromium with `--enable-unsafe-webgpu`).
  2. Parse WebGPU validation layer messages, pipeline compilation logs, and GPU timestamp query buffers.
  3. Evaluate against stopping criteria:
     - Zero validation errors.
     - Execution time ≤Target Budget (e.g., 2.0 ms).
     - Zero driver resets/TDRs.
  4. Formulate structured failure logs or approve pipeline output.

### Profiler Harness Execution Flow
1. **Environment Setup:** Playwright boots a headless Chromium browser with flags:
   - `--enable-unsafe-webgpu`
   - `--disable-gpu-sandbox`
   - `--enable-features=Vulkan,UseSkiaRenderer`
2. **Buffer Allocation &amp; Binding:** The harness reads the `MathSpec`, generates synthetic typed array data buffers (e.g., `Float32Array`), and mounts them into GPU storage buffers (`GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_SRC | GPUBufferUsage.COPY_DST`).
3. **Timestamp Query Pipeline:**
   - Checks for `timestamp-query` feature support on the `GPUDevice`.
   - Allocates a `GPUQuerySet` of type `"timestamp"` with capacity for 2 queries (Pass Start, Pass End).
   - Encodes `writeTimestamp` calls before and after the compute pass.
   - Resolves query sets to a buffer, maps it to CPU memory, and calculates:
     ΔTGPU​=Timestamp Period (ns)Timestampend​−Timestampstart​​×10−6 ms
4. **Validation Catch:** Listens to `device.pushErrorScope('validation')` and catches any asynchronous errors raised during `createComputePipeline` or `dispatchWorkgroups`.

## 5. Loop Mechanics, Safety Safeguards &amp; TDR Mitigation
### Loop Control Flow
```

                                      │
                                      ▼
                           Iteration = Iteration + 1
                                      │
                                      ▼

                                      │

                  │                        │                             │
                  │              Time > Target Budget          Time <= Target Budget
                  │                        │                             │
                  │                        ▼                             ▼
                  │             Push Optimization Hints           Set Status = PASSED
                  │                        │                             │

                                NO                                       │

```
### Safety &amp; Robustness Controls
1. **Timeout Detection and Recovery (TDR) Prevention:**
   - Executing infinite loops or massive unrolled grids in WebGPU triggers OS-level GPU driver resets (TDR).
   - **Mitigation:** The harness injects a hardware guard into `ShaderArtifact` before execution: clamping global invocation IDs and capping max loop iterations to a safe baseline (106 ops) during profiling.
2. **Memory Alignment Guardrails:**
   - WGSL requires layout alignment rules for uniform and storage buffers (e.g., `vec3` alignment is 16 bytes; arrays of `vec3<f32>` require explicit padding to 16-byte strides).
   - **Mitigation:** The Math Architect automatically transforms structural layouts by appending explicit padding variables (`_padding: f32`) or rewriting structure arrays to Structure-of-Arrays (`SoA`) configurations.
3. **Loop Short-Circuiting:**
   - If Agent 3 returns an identical error twice consecutively, the loop breaks early and prompts the Math Architect to re-evaluate the core algorithm strategy (e.g., switching from single-pass to multi-pass compute).

3. **`templates/`:** Houses Jinja2 templates used by the **Dispatch &amp; Diagnostic Assembler** stage to generate plug-and-play TypeScript host drivers (`webgpu_app.ts.jinja2`) and diagnostic reports for the user.
4. **`scripts/setup_environment.sh`:** Automates installing both Python runtime dependencies and fetching native Chromium binaries required for headless WebGPU compute testing
